# Mineflayer 多账号挂机机器人 · 项目结构说明

> 本文档说明机器人项目中**每个文件夹与文件的作用**，便于快速了解、二次开发与交接。
> 副本位置：`E:\mineflayer-bot`（**已包含依赖与内置 Node 运行时，新电脑双击即用**；不含本地服务器文件、运行日志与正版授权缓存）。

---

## 一、项目简介

基于 **Mineflayer（Node.js）** 的 Minecraft 多账号挂机机器人，附带本地 Web 控制面板。

- **技术栈**：Node.js（JavaScript CommonJS）+ Mineflayer + mineflayer-pathfinder，**零构建**，无需编译。
- **核心能力**：多账号同时在线、Web 可视化面板、**面板可脱离 MC 服务器独立运行（支持 0 账号纯面板，先配置后连接）**、聊天防刷屏、断线自动重连、权限白名单、防 AFK、自动进食、灾厄之瓶定时饮用、正前方防身攻击、传送指令排队等。
- **设计原则**：
  1. 一切对外发言/指令统一走聊天队列（防刷屏、防非法字符）；
  2. 一切资源可注销（断线清理、进程退出两级清理，避免内存泄漏）；
  3. 进服默认所有自动功能**关闭**，收到指令后才开启；
  4. 接受指令后静默执行，回复一律走私聊、不在公屏说话。

## 三、`src` 源代码结构

源代码按职责分为 6 个部分：入口 `main.js`、核心层 `core`、服务层 `services`、指令层 `commands`、行为层 `behaviors`、工具层 `utils`。

### 1. 入口

| 文件        | 作用                                                                                                                                               |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `main.js` | 程序入口。加载并校验配置 → 创建并启动全部机器人 →（可选）启动 Web 面板 → 等待退出信号并优雅关闭。<br>用法：`node src/main.js`（默认配置）或 `node src/main.js config/local-offline.config.js`（指定配置）。 |

### 2. `core` 核心编排层（4 个文件）

> 说明：`ServerMetrics.js`（TPS/Ping 采集）实际位于 `services\` 目录，详情见下一节。

| 文件                   | 作用                                                                                                                                                                                                                                                                                                                                                    |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BotManager.js`      | **多账号编排层**。负责错峰串行启动各账号、等待上线、汇总状态、统一停止；提供面板用的增删机器人、改登录方式、改服务器、启用/停用账号、白名单管理等接口。单账号故障不影响其他账号。**同名账号规则：同一台服务器上只能有一个（重复添加提示“账号已存在”）；换台服务器（IP/端口不同）允许再加同一个账号，并会提醒“正版账号同一时间只能在一个服务器在线，两边都开着会互相顶下线”**。**账号唯一标识 = `账号名@服务器:端口`**（`_keyOf`）：同名账号挂多台服时每条件一张卡片，卡片按钮 / 启用停用 / 删除 / 控制台选账号都只作用于那一张卡。**“在线/离线”状态汇总行每 5 分钟打一行（启动时先打一行），中文显示（在线/离线/重连/等服务器上线/已停用等）**。 |
| `BotContext.js`      | **单个机器人的容器（集成核心）**。为一个账号装配 pathfinder、防AFK、聊天队列、传送队列、白名单、自动进食、问候、指令系统；管理生命周期（离线/连接中/在线/重连中/等服务器上线/已停止/已放弃）；实现死亡自动重生回家、两级资源清理，以及清空、移动、攻击、喝瓶等高层动作。另有「远处区块定期清理」（`perf.keepChunks`）与「内存告急就地清理」`memoryClean(soft                                                                                                                                           |
| `TaskRunner.js`      | **行为任务串行执行器**。让回家、跟随、进食、移动等任务严格排队串行；支持任务超时、中断，以及“死亡—回家—再死亡”类快速空转检测。                                                                                                                                                                                                                                                                                   |
| `ReconnectPolicy.js` | **断线重连策略**。指数退避（2s→4s→8s…封顶 5 分钟）+ 随机抖动；连续失败 10 次进入 30 分钟长冷却；能识别踢出原因：封禁/白名单问题直接放弃并告警，服务器维护走长冷却，网络问题正常退避。退避到点先由 `ServerProbe` 探一次服务器：不在线就保持离线不直连（只探测），在线才真连。                                                                                                                                                                                           |

> 补充：`ServerMetrics.js`（面板卡片 TPS / Ping 采集）文件位置在 `services\`，功能说明见下一节 `services` 表格。

### 3. `services` 基础服务层（12 个文件）

| 文件                 | 作用                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ServerMetrics.js` | **面板卡片上的 TPS / Ping 采集**。每连接一次重新绑定：`bindBot(bot)` 每秒采一次，解绑后不再报数（不会给已断开的连接报数）。TPS = 服务器世界时间 `bot.time.age`（每服务器 tick +1）在 10 秒滑动窗口里的增量（上限 20，服务器卡死如实算 0；窗口没攒够/拿不到时间包 → `null`，面板显示 `-`，不编数）；Ping = `bot.player.ping`（服务器广播的 player_info latency，和游戏里 TAB 看到的一致；没广播 → `null`）。采样间隔/窗口可用配置项 `metrics.windowMs` / `metrics.intervalMs` 改。                                             |
| `ChatQueue.js`     | **聊天/指令队列（防刷屏核心）**。全项目唯一发言出口，任何模块不得直接 `bot.chat()`。提供令牌桶限流（约 1.5s/条）、相同内容去重、超长文本切分、消息优先级、队列上限保护；并净化文本（移除 §/DEL、把换行等控制字符转空格），防止“Illegal characters in chat”被踢。                                                                                                                                                                                                                     |
| `WarpQueue.js`     | **传送指令队列（传送防刷屏）**。覆盖 `tpa`、`tpahere`、`home`、`sethome`、`delhome`。同一时刻只允许一个传送在途，两次之间有最小间隔；回家等即时传送会等待位置变化或确认文本、超时可重试；请求类只等“请求已发送”。                                                                                                                                                                                                                                                   |
| `Whitelist.js`     | **聊天指令权限模型（三组权限）**。组1 owners（全部指令，含管理类）> 组3 **传送白名单管理员 tpAdmins（白名单组那套指令 + 传送白名单三条 `tpadd`/`tpremove`/`tplist`；管理类指令仍然只给 owner）** > 组2 白名单组 friends（按指令名放行，见 `whitelist.friendCommands`）> 其他人（默认不响应）；另有**传送白名单成员 tpPlayers**（不是角色组，只是“自动接受传送”这一项权限，由组3/owner 添加）、最高优先级黑名单、临时授权、每人每权限点冷却。`canAcceptTpa(name)` 决定谁能享受自动 `/tpaccept`（owners / tpAdmins / friends / tpPlayers，黑名单除外）。 |
| `ChatMonitor.js`   | **服务器公屏消息环形缓冲**。汇总各机器人收到的公聊与系统广播（加入/退出等），多账号收到同一条时按内容去重；默认保留最近 200 条，支持按编号增量拉取，供 Web 面板实时显示；同时记录私聊指令、**公屏指令**与机器人回复（含对方名字）。                                                                                                                                                                                                                                                       |
| `ChatLogger.js`    | **聊天日志落盘**。全量聊天写入 `logs/chat/<账号>/日期.log`；私聊汇总写入 `logs/whisper/日期.log`（跨账号并标明方向）。                                                                                                                                                                                                                                                                                                 |
| `ConfigStore.js`   | **面板改动持久化**。把 Web 面板上对默认服务器、**每个账号各自的独立服务器（不同账号可连不同服）**、账号、白名单（好友名单 / 好友组可用指令 / **传送白名单 tpPlayers** / **传送白名单管理员 tpAdmins**）的修改保存到 `<配置名>.panel.json`，只存可变部分，不重写带中文注释的原始配置；启动时由 configLoader 自动合并。                                                                                                                                                                                |
| `WebDashboard.js`  | **Web 控制面板（零依赖，Node 内置 http）**。默认只绑定 `127.0.0.1`。提供状态/控制台页面、`/api/status`、`/api/chat`、`/api/control` 等接口；写操作需随机访问令牌并校验同源来源；含机器人卡片（**同一账号挂多台服时每条件一张卡片，按 `账号@服务器:端口` 区分、标题带 `@服务器`**；卡片内指令为**折叠菜单**：常用/移动·朝向/家·传送/瓶子·攻击/账号，刷新不收起你展开的组）、指令控制台、服务器/账号管理、白名单管理（**「白名单组可用指令」那排勾选框可折叠**，白名单窗口常显；含**传送白名单**与**传送白名单管理员**两张名单的指定/移除）、控制台日志与服务器公屏双窗口（「控制台日志」栏右上角有**刷新**按钮：只重画这一栏日志，并补拉可能漏掉的玩家指令与机器人回复，不会刷新整页、不动机器人状态）。                                       |
| `Notifier.js`      | **通用事件通知（可选，默认关闭）**。通过通用 Webhook 推送死亡、放弃重连、长时间故障等关键事件，同时发送 text 与 content 字段（兼容 Discord）；未配置则不启用，推送失败不影响挂机。                                                                                                                                                                                                                                                                       |
| `BottleRunner.js`  | **灾厄之瓶（ominous_bottle）定时饮用**。`瓶子 开 <分钟>` 立即喝一瓶并按分钟定时，`瓶子 关` 停止；提供任务开关、距下一瓶剩余秒、omen 类增益剩余秒、袭击血条进度。因瓶子不在 Mineflayer 可消耗清单、饱食满时 `consume()` 会误报，这里改用 `activateItem()` 自行饮用并以冷却包/超时判定结束。                                                                                                                                                                                              |
| `AttackRunner.js`  | **正前方定时攻击（防身/挂机挥击，非 killaura）**。`攻击 <x>` 每 x 个游戏刻（20tick=1秒）攻击一次准星正前方射线命中的实体，`攻击 关` 停止。不自动瞄准、不转向、不追踪；前方无实体时仅空挥手臂。                                                                                                                                                                                                                                                                 |
| `ServerProbe.js`   | **服务器在线探测（服务器列表 ping）**。机器人连不上时先探一次服务器（与客户端“刷新服务器”同一条协议，支持 SRV/域名解析，带超时）：**不在线就保持离线、不再发登录包**，按 `serverWatch.intervalMs`（默认 10 秒）持续探测，一探测到在线立即回调重连，并把延迟/在线人数写进日志。同一个 host:port 的所有机器人共用一份探测，没人等待时自动停表。                                                                                                                                                                             |
| `ChestManager.js`  | **箱子 / 木桶自动存取**。参考 mineflayer 官方 `examples/chest.js` 的标准流程：`findBlock(箱子类方块) → bot.openContainer → chest.deposit/withdraw → chest.close`。在其之上补齐挂机场景需要的：①先寻路到仓库点（走不到就明确报错，不干等）；②开箱 / 存 / 取 / 关**每一步都有超时**，失败自动关窗口，不留半开的容器；③**规则引擎**——`keep`（永远留身上）/ `deposit`（会自动存进箱子的名单）；④同一时刻只允许一个容器操作（经 TaskRunner 串行，不和移动/进食打架）；⑤支持定时自动存箱（`autoScheduleMs`）。物品名**支持中文**（`!取 铁锭 64`，对照表见 `utils/itemNames.js`，含 221 个常用物品；也兼容英文 ID）（多机器人抢同一个箱子窗口必然互相顶掉）。 |

### 4. `commands` 聊天指令层（10 个文件）

| 文件            | 作用                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `index.js`    | **指令注册/解析/权限/冷却核心（CommandRegistry）**，同时导出 `loadAllCommands()`（指令目录，面板权限勾选框与权限校验都用它）。公聊需带前缀（默认 `!`），主管与白名单私聊可省前缀；流程为解析指令名 → **（仅私聊指令在此拦掉公屏来源）** → 权限校验 → 冷却 → 执行；无权限默认静默；回复统一私聊并经 ChatQueue，同时把指令与回复送入控制台日志。<br>**仅私聊机制（`whisperOnly`）**：指令定义里标了 `whisperOnly: true` 的，来源是公屏时直接静默忽略（不执行、不回复，拦截在权限校验之前）。原因：公屏是服务器广播的，同服每个机器人都会收到同一条并各自执行一遍（多份动作 + 多份回执，`!回家`/`!tpa`/`!清空` 还会互相撞位置、互相捡走丢出物），而私聊天然只发给一个机器人。当前 45 条指令中 **30 条仅私聊、15 条公屏可用**（`!停止`/`!重连`/`!关服`/`!afk`/`!进食`/`!实体过滤`/`!说` 与 8 条白名单管理指令保留公屏）。 |
| `status.js`   | 状态查询指令 `!状态/!status`：回复在线状态、坐标、血量、饥饿、维度、在线时长、背包占用、已开启任务、增益与袭击信息。**仅私聊。**                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `movement.js` | 移动类指令：`!停止`、`!回家`、`!跟随 <玩家>`、`!去 <玩家>`、`!afk 开/关`。**其中 `!回家`/`!跟随`/`!去` 仅私聊；`!停止` 与 `!afk` 保留公屏可用**（全体急停/开关，一起触发是正确的）。                                                                                                                                                                                                                                                                                                                                                                                |
| `warp.js`     | 传送请求指令（经 WarpQueue）：`!tpa <玩家>`、`!tpahere <玩家>`、`!设家 [家名]`、`!删除家 [家名]`——家名一律默认 `1`，不填也会把 1 带进命令（`sethome 1`/`delhome 1`/`home 1`），避免裸命令在部分服务器上返回家列表或失败。**四条全部仅私聊。**（`!回家 [家名]` 在 `movement.js` 中）                                                                                                                                                                                                                                                                                                     |
| `detect.js`   | 盯人检测指令：`!检测 <玩家1> <玩家2>`——盯着玩家1，**他一离开服务器就自动对玩家2执行 `/tpa`**；**两个参数都必填**（缺玩家2 会提示补参数，玩家1 与玩家2 不能同名）；`!检测` 看当前在盯谁，`!检测 关 [玩家1]` 取消。权限点 `warp`（默认只有最高权限组，可在面板勾给白名单组）。**仅私聊。**                                                                                                                                                                                                                                                                                                                            |
| `bottle.js`   | 灾厄之瓶指令：`!瓶子 开 <分钟>`、`!瓶子 关`。**仅私聊。**                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `chest.js`    | 箱子 / 木桶存取指令（经 ChestManager）：`!存箱 [全部]`（按 `chest.deposit` 名单存，加「全部」则除 `chest.keep` 外全存）、`!取 <物品> [数量]`（数量留空 = 尽量取）、`!开箱`（只看看有什么）。**三条全部仅私聊。** 需先在配置里填仓库点：`chest.station` 坐标，或只配 `chest.stationAlias` 走服务器 home 指令回家再找。 |
| `features.js` | 功能开关指令：`!进食 开/关`（自动进食，进服默认关闭）、`!实体过滤 开/关`。**均保留公屏可用**（全体开关类）。                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `robot.js`    | 机器人动作类指令（**本文件全部仅私聊**）：`!清空`（一次性丢出全部物品，含盔甲/副手）、`!攻击 <tick>/关`、`!移动 x y z [距离]`（默认距目标 0.3 格）、`!移动 东/西/南/北 格数`、`!指令 <服务器指令>`（仅执行允许转发列表内的指令）、`!说 <内容>`（把内容作为普通聊天发到服务器公屏，跨机器人只发一次）、`!左转 [角度]`/`!右转 [角度]`（原地转动视角，默认 90°）、`!俯视 [角度]`、`!瞄 <x> <y> <z>`、`!切 <1-9>`、`!副手`、`!丢`、`!种树`、`!装备`、`!卸甲`、`!右键`、`!下车`、`!持续右键`。<br>例外：`!说` 标为**公屏可用**（它本身有跨机器人去重 `claimSay`，同一句只会由第一个机器人发出）。                                                                                                                             |
| `admin.js`    | 管理指令（默认仅主管 owner，全部**保留公屏可用**）：`!重连`、`!关服/!下线`、`!授权 <玩家> [分钟]`（临时授权，默认 60 分钟）、`!白名/!加白 <玩家>`、`!清白/!移除白名 [玩家]`、`!白名单`、`!传送管理员 [删] <玩家>`、`!传送白名 <玩家>`、`!传送清白 <玩家>`、`!传送名单`。                                                                                                                                                                                                                                                                                                                             |

### 5. `behaviors` 行为插件层（7 个文件）

| 文件                | 作用                                                                                                                                                                                                                                                                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `autoAuth.js`     | **自动登录 / 注册**。适配有登录插件的服务器（AuthMe 类）：进服后监听服务器文本，命中「请登录」类文案发 `/login <密码>`、命中「请注册」类发 `/register <密码> <密码>`，识别到「登录成功 / 欢迎回来」即确认完成。**安全设计**：没配密码则整个功能**不启用**（绝不发空密码）；同一条提示短时间内不重复发、两次尝试至少间隔 `retryMs`（默认 8 秒，防被判刷屏）；命中「密码错误」立即放弃，超过 `maxAttempts`（默认 5 次）也放弃并告警（不拿错密码死循环）；**日志与面板中密码一律显示 `***`**。每次进服（含重连）都会 `reset()` 重新判断登录状态。 |
| `antiAfk.js`      | **防 AFK 行为（Mineflayer 插件，丢/捡物品版）**。进服默认全关，`!afk 开` 后启动：①拾取循环只原地捡贴身自动吸附范围内的掉落物，不追远处、不区分谁丢的；②丢捡循环在原地朝下丢 1 个廉价物品到脚下再原地捡回。`!afk 关` 停丢、保留贴身拾取；断线后回到全关。                                                                                                                                                                                                             |
| `autoEat.js`      | **自动进食（自写轻量插件）**。饥饿值低于阈值（默认 14）自动取食，排除腐肉/毒食等负面食物；进食作为任务经 TaskRunner 串行执行，不与移动任务冲突。                                                                                                                                                                                                                                                                            |
| `entityFilter.js` | **实体过滤（可选，默认关）**。`!实体过滤 开/关`：类型不在 `keepTypes`（默认 player/item）里的实体不进机器人内存（写不进/读不到/不遍历），服务器刷再多怪也不拖累机器人。★ **近身 8 格内（`perf.entityFilter.keepNearRadius`）的实体一律保留**，所以 `!攻击` 这类要走 `bot.entityAtCursor()` 的功能照常生效（改成 0 = 老行为、只能空挥）；另有 `keepNearMax`（默认 40）上限与 10 秒定时清扫（清未解析空壳、清走远的怪）兜底。                                                                              |
| `greetings.js`    | **进服问候 / 玩家加入欢迎**。挂机场景默认全部关闭以免主动发言刷屏；需要时在配置开启，所有发言经 ChatQueue 受限流约束。                                                                                                                                                                                                                                                                                          |
| `tpaAcceptor.js`  | **自动接受传送请求**。可自动接受名单（owners / **tpAdmins 传送白名单管理员** / friends / **tpPlayers 传送白名单成员**）对机器人 `tpa`/`tpahere` 时自动发出 `/tpaccept`（命令与冷却可配 `autoAcceptTpa`，默认开启）；黑名单与其他玩家一律忽略。同一条消息经 chat/messagestr 双事件到达只处理一次，同一玩家 5 秒内只接受一次；识别不了的请求文案会写 warn 日志，便于按服务器实际文案继续适配。                                                                                                  |
| `playerWatch.js`  | **盯人检测（playerWatch）**。`!检测 <玩家1> <玩家2>` 注册后等**玩家1**离开服务器：信号源① mineflayer 的 `playerLeft`（玩家列表里消失，与服务器文案无关）；②公屏/系统里的「X 离开了游戏 / 下线」文案兜底。命中后经 `WarpQueue.tpa(玩家2)` 发 `/tpa`（排队+限流），**只触发一次、触发完自动解除**（要再盯得重新发命令）；**同一时间只按最新那条检测算**（重复输入会顶掉之前的，含同名玩家的旧目标）；同一玩家 10 秒内只允许触发一次，且同一进程里由第一个发现的机器人执行（避免多个机器人一起 tpa）。**两个参数都必填**（玩家2 不再默认 玩家B），且玩家1 与玩家2 不能同名。该指令**仅私聊**。 |

### 6. `utils` 工具层（7 个文件）

| 文件                | 作用                                                                                                                                                                                                              |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `configLoader.js` | **配置加载与校验**。启动时读取配置，字段有误会收集全部问题并抛出中文错误，未提供的可选块自动补默认值；并自动合并面板持久化覆盖层（.panel.json）。                                                                                                                                |
| `logger.js`       | **结构化日志**。控制台彩色输出 + 按天滚动写入 `logs/runtime/`。用法：`createLogger('账号名')` 后调用 `.info/.warn/.error/.debug`。                                                                                                            |
| `helpers.js`      | **通用工具函数**：等待（sleep）、随机整数、查找在线玩家、随机令牌、文本切分等。                                                                                                                                                                    |
| `dailyFile.js`    | **按天滚动的追加文件写入器**，文件名 `<前缀>YYYY-MM-DD.log`，跨天自动切换新文件（日志类服务的基础）。                                                                                                                                                  |
| `memoryGuard.js`  | **进程内存看门狗（先清理、后重启，目标是不断线）**。定时读 V8 堆用量：≥70% 告警；≥78% 调 `BotContext.memoryClean('soft')` 就地清理（卸远处区块 + 强制 GC）；≥85% 升级为硬清理（只留身边 2 区块 + 丢掉怪/动物实体 + 再 GC）；只有清理后仍然 ≥95% 才优雅重启兜底（交给 `start.bat` 的循环拉起）。清理全程不做任何下线/重连动作。 |
| `memProbe.js`     | **内存明细探针（默认关，排查「堆一直涨」时才开）**。设 `MEM_PROBE=1`（见 `诊断内存.bat`）后每 60 秒往运行日志写一行「内存明细」：堆/常驻/外部内存、句柄数、活跃资源类型，以及每个账号的 实体数・区块数・监听器数・协议监听数・记分板条目・bossbar・队伍・发送队列・任务队列・过滤隐藏数——对比前后两行就能看出是谁在涨。                                |
| `walk.js`         | **确定性简单直线行走（不使用 pathfinder 的 A* 寻路）**。适用于平坦地形/短距离；因 pathfinder 在 26.1.2 复杂寻路时会长时间挂起，固定点附近直线行走更可靠。                                                                                                               |

## 六、如何启动

> 全新电脑首次使用，建议直接看同目录 **《新电脑快速上手.md》**（含步骤与常见问题）；以下为简要说明。

1. **准备环境**：安装 Node.js（建议 18/20 以上）。
2. **真实服（正版）**：双击 `start.bat`（首次自动 `npm install`；正版首次按控制台提示打开链接输入代码授权）。
3. **本地离线测试**：先启动本地 Minecraft 服务器（`online-mode=false`），再双击 `start-local.bat`。
4. **手动启动**：

   ```bash
   npm install                # 首次安装依赖
   node src/main.js           # 默认配置
   node src/main.js config/local-offline.config.js   # 指定配置
   ```
5. **打开面板**：机器人启动后，浏览器访问 `http://127.0.0.1:8848`（端口以配置为准）。

## 七、依赖、运行时与“未包含”的内容

**已随副本包含（新电脑无需安装任何东西，整份拷贝后双击 `start.bat` 即可）：**

| 已包含                | 说明                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `node_modules`     | 全部 npm 依赖（mineflayer、mineflayer-pathfinder 等），约 449 MB；启动脚本用 `node -e "require.resolve('mineflayer')"` 真实校验，只有损坏时才会触发重装。 |
| `runtime\node.exe` | 内置的 Node.js 运行时（v24.18.1，Windows x64，约 88 MB）。启动脚本优先用它，因此**新电脑不需要先装 Node.js**；若删掉该目录，会自动回退使用系统 PATH 里的 Node.js，都没有则提示安装。 |

**未包含：**

| 未包含          | 原因 / 如何恢复                                                                        |
| ------------ | -------------------------------------------------------------------------------- |
| `logs`       | 历史运行/聊天日志，非程序文件，运行后自动重新生成。                                                       |
| `auth-cache` | 正版登录授权缓存（含敏感令牌），不随副本传播；正版首次启动重新授权即可。                                             |
| `npm`        | npm 本体约 459 MB，日常运行用不到（依赖已附带），故不打包；只有依赖损坏需要重装时才用得到，届时装一次 Node.js LTS 即可（自带 npm）。 |
| `_research`  | 含**本地服务器文件**（server.jar、世界存档）、一次性研究/诊断脚本与第三方克隆参考，按要求不带服务器文件，故整体剔除。               |
