## 一、项目定位

一个**多账号、确定性、零构建、配置驱动**的 Minecraft 挂机机器人框架：

- 写一次行为，配置文件里声明多个账号同时运行；
- 开箱即用：`npm install` 后双击 `start.bat` 或 `node src/main.js`；
- 7×24 稳定挂机：自动登录、防 AFK、防刷屏、自动进食、断线指数退避重连；
- 核心特色：**聊天/传送全排队防刷屏、箱子/木桶自动存取、白名单权限、私聊日志落盘**；
- 不依赖大模型（不花 API 费、行为确定可复现）；Web 面板仅作为后期可选增强。

与竞品的形态差异：比 Afk-Bot/TrafficerMC 工程化且修掉泄漏与重连缺陷；比 blockmine 轻量（无数据库、无前端构建）；比 mindcraft 确定、免费、适合挂机。

## 四、总体架构

分四层（图形版见《03-架构蓝图.html》）：

```
┌──────────────────────────────────────────────────────────┐
│ 入口层   src/main.js                                      │
│   读取并校验配置 → 启动 BotManager → 进程信号优雅退出       │
├──────────────────────────────────────────────────────────┤
│ 编排层   core/BotManager.js                               │
│   多账号生命周期、错峰启动、状态汇总、单账号故障隔离         │
├──────────────────────────────────────────────────────────┤
│ 容器层   core/BotContext.js  +  TaskRunner + Reconnect    │
│   单 bot 装配：插件/事件/行为/服务；cleanup 注册表；       │
│   任务串行执行（超时/中断/循环检测）；指数退避重连          │
├──────────────────────────────────────────────────────────┤
│ 行为与服务层                                              │
│   ChatQueue  WarpQueue  ChestManager  Whitelist           │
│   ChatLogger  antiAfk  autoAuth  autoEat  聊天指令        │
└──────────────────────────────────────────────────────────┘
        基础设施：utils/logger（结构化+按天滚动）、configLoader（校验）
```

**两条关键设计主线：**

1. **一切资源可注销**：BotContext 维护 cleanup 注册表，所有 interval/timeout/事件监听注销函数都登记；断线重建时先 `destroy()` 旧实例（逆序清理全部资源）再建新 bot —— 根治 Afk-Bot/TrafficerMC 的泄漏问题。
2. **一切对外动作走队列**：行为模块不允许直接 `bot.chat()`，统一进 ChatQueue；传送类进 WarpQueue；行为动作走 TaskRunner 串行 —— 根治并发刷屏与动作打架。

## 六、核心模块设计

### 6.1 BotManager（编排层）
- 按配置逐个创建 BotContext，**错峰启动**（默认间隔 3~10 秒可配），避免同时进服触发反压测。
- 维护 `Map<账号, BotContext>` 与状态机：`disabled / connecting / waitingAuth / online / reconnecting / dead`。
- 对外方法：`startAll / stopAll / restartOne / getStatus`；控制台周期打印各账号状态表。
- **故障隔离**：单个 bot 的同步异常在 context 内捕获并触发重连；连续失败超限只标记该账号，其他账号不受影响。
- 捕获 Ctrl+C / 窗口关闭：先对所有 bot 发 `quit()`，确认退出后再结束进程。

### 6.2 BotContext（容器层）
- 封装单个 bot：加载插件（pathfinder 等）、挂载事件、实例化该账号专属的队列与行为。
- `registerCleanup(key, fn)`：登记清理函数；`destroy()`：逆序执行清理（清定时器、移除监听、关闭打开的窗口、quit）。
- 重连时**整体重建 bot 但保留配置与统计**，旧实例资源全部释放。
- 对应解决：Afk-Bot 定时器泄漏、TrafficerMC 监听器泄漏。

### 6.3 TaskRunner（动作执行，借鉴 mindcraft ActionManager 并去 LLM）
- 行为动作（回家、存箱、跟随、采集）统一为任务，**严格串行**，避免 pathfinder/挖掘互相打断。
- 每个任务支持：超时强制结束、中断信号（同时 `pathfinder.stop()/stopDigging()/collectBlock.cancelTask()`）。
- **快速循环检测**：同类任务高频重复（如死亡-回家-再死亡）超阈值时暂停并告警，不做空转死循环。
- 任务状态可查：`pending / running / done / failed / cancelled`。

### 6.4 ReconnectPolicy（重连策略）
- 指数退避：2s → 4s → 8s … 封顶 5 分钟，加 ±20% 随机抖动。
- 连续失败 10 次进入 30 分钟长冷却后继续，不轻易放弃；重连成功则计数清零。
- 识别踢出原因关键词并区别处理：
  - "维护 / restarting / maintenance" → 等待长冷却；
  - "whitelist / 白名单 / banned" → 停止该账号重连并告警（重试无意义）；
  - 网络错误（ECONNREFUSED/超时）→ 正常退避。
- 对应解决：竞品固定延迟重连、重连风暴、无意义重试。

### 6.5 ChatQueue（聊天/命令队列）—— 防刷屏核心
- 全项目唯一出口：任何聊天、指令都入队，禁止模块直接 `bot.chat()`。
- **令牌桶限流**：默认每 1.5 秒一条（可配）；普通聊天与命令分通道。
- 相同内容冷却去重；超长消息自动切分；队列设上限，溢出丢弃低优先级并记录。
- 优先级：主人指令响应 > 系统命令（login/home 等）> 定时闲聊。

### 6.6 WarpQueue（传送队列）—— 传送防刷屏
- 传送类指令（`/spawn /home /warp /tpa /rtp` 等，正则可配）单独队列，**同一时刻只允许一个在途**。
- 发出后等待"完成信号"：位置变化达到阈值 / 服务器确认文本 / 超时（默认 10s）。
- 在途未结束时，后续传送排队等待；失败按策略重试一次；两次传送默认最少间隔 3 秒。

### 6.7 ChestManager（箱子/木桶自动存取）
- 配置"仓库点"坐标，bot 经 pathfinder 到达后按方块类型打开 `chest / trapped_chest / barrel`。
- 容器操作封装为可等待方法：`open / deposit / depositAll / withdraw / close`，带超时与重试。
- 规则引擎（每账号可配）：
  - `deposit`：指定物品（矿石/掉落物）入箱；
  - `keep`：保留工具/食物在身上；
  - `withdraw`：按数量取出；
- 触发方式：定时（如每 30 分钟）、背包将满、主人 `!存箱` 指令。

### 6.8 Whitelist（权限）
- 三级：`owners`（全部指令）> `friends`（指定指令）> 其他人（**默认不响应任何指令**，防止被陌生人利用）。
- 支持黑名单、临时授权、指令级权限点、每人每指令冷却。
- 所有聊天指令先过权限再进入 TaskRunner。

### 6.9 ChatLogger（日志）
- 全量聊天按天滚动、分账号目录；**私聊单独成档**（时间戳、双方、内容）。
- 服务器系统消息（登录提示、菜单文本）一并记录，便于后期适配。
- 密码、会话等敏感内容脱敏后再写日志。

### 6.10 antiAfk（防 AFK）
- **随机化动作池**：随机间隔（20~90 秒）随机选择——转头、跳一下、走几步再回来、挥手。
- 不采用"一直按潜行/跳跃"的机械模式（Afk-Bot 模式易被反作弊识别）。
- 动作池、强度、间隔均可配；全部定时器登记 cleanup。

### 6.11 autoAuth（自动登录）
- 进服后按聊天关键词（"登录/注册/login/register"，可配）判断状态：
  - 未注册 → `/register <密码> <密码>`；已注册 → `/login <密码>`；
- 支持二次确认、聊天验证码、简单 GUI 菜单点槽位（按服务器实际形式适配）。
- 登录成功前挂起其他主动行为，防止未登录乱发指令。

### 6.12 autoEat（自动进食）
- 饥饿值低于阈值（默认 14）自动取食，排除腐肉/毒食；进食作为任务经 TaskRunner 执行，期间暂停移动类任务。

### 6.13 聊天指令系统（主人远程控制）
- 指令统一注册：`名称 / 别名 / 用法 / 权限点 / 冷却 / execute`。
- 一期指令清单（建议）：
  - `!状态`（在线/坐标/血量/背包概览）
  - `!回家`、`!去 <玩家>`、`!跟随 <玩家>`、`!停止`
  - `!存箱`、`!取 <物品> <数量>`
  - `!重连`、`!关服`（停止该 bot）
- 所有回复经 ChatQueue 发出，指令本身不触发刷屏。

## 九、验收标准

1. `npm install` 后双击 `start.bat`（或 `node src/main.js`）可启动全部启用账号；
2. 配置字段错误时启动即给出明确中文报错，不运行到一半才崩；
3. 反复断线重连后，定时器/监听器数量稳定（无泄漏）——用句柄/定时器计数实测；
4. 快速连续触发聊天/传送时，日志可见排队，实际发包频率不超过配置，不被服务器刷屏判定踢出；
5. 全部私聊按天落盘，内容与时间戳完整；
6. 任一账号被封/崩溃/维护，其余账号继续正常运行；
7. Ctrl+C 后 bot 全部正常退出，无残留进程。

## 十、合规与风险边界

- 仅用于**自己拥有/授权的账号**，遵守目标服务器规则；
- 不做刷屏轰炸、不绕过封禁、不提供攻击玩家的 killaura 类功能（PVE 自保除外且默认关闭）；
- 配置文件含登录密码，仅本地保存，日志脱敏；
- 风险提示：服务器反作弊策略变更可能导致 bot 被踢，需按实际情况调整 antiAfk/限流参数。
